A Field Guide to This Blog

Every element a post can use, demonstrated on a coin that may or may not be fair.

Contents

    This post doubles as a style guide. Each section uses a different element—math, code, figures, tables, callouts—so I can see how they look together before writing anything real. To keep it from being pure filler, everything is in service of one question: how many times do you need to flip a coin to know whether it's fair?

    Text and Inline Elements

    Body text supports the usual inline formatting: bold for emphasis, italics for terms or titles, links, and inline code for function names like rbinom(). You can also highlight a key phrase, mark something as wrong corrected, define an abbreviation like MLE (hover it), or show a keyboard shortcut such as Cmd + Enter.1

    Lists

    Unordered lists work for loose collections:

    • A coin has some unknown probability \(p\) of landing heads.
    • We flip it \(n\) times and count the heads, \(X\).
    • We want to say something about \(p\) using only \(X\).
      • Nested items are indented one level.
      • And can mix in code or math like \(X \sim \text{Binomial}(n, p)\).

    Ordered lists work for steps:

    1. Pick a sample size \(n\).
    2. Flip the coin \(n\) times.
    3. Estimate \(p\) with the proportion of heads.

    Math

    Inline math sits inside a sentence: the natural estimate of \(p\) is \(\hat{p} = X / n\), the fraction of flips that came up heads. Longer expressions get their own line:

    \[ \hat{p} = \frac{1}{n} \sum_{i=1}^{n} X_i, \qquad \mathbb{E}[\hat{p}] = p, \qquad \operatorname{Var}(\hat{p}) = \frac{p(1-p)}{n}. \]

    Write inline math between \( and \), and display math between \[ and \]. Anything LaTeX-like works.

    Definitions, Theorems, and Proofs

    Definition 1. An estimator \(\hat{\theta}_n\) is consistent for \(\theta\) if, for every \(\varepsilon > 0\), \(P(|\hat{\theta}_n - \theta| \geq \varepsilon) \to 0\) as \(n \to \infty\).

    Theorem 1 (Weak Law of Large Numbers). The sample proportion \(\hat{p}\) is a consistent estimator of \(p\).

    Proof. By Chebyshev's inequality, for any \(\varepsilon > 0\),

    \[ P(|\hat{p} - p| \geq \varepsilon) \leq \frac{\operatorname{Var}(\hat{p})}{\varepsilon^2} = \frac{p(1-p)}{n\varepsilon^2} \leq \frac{1}{4n\varepsilon^2}, \]

    which goes to zero as \(n \to \infty\).

    Note

    Callouts come in three flavors. This blue note is for asides that add context without being essential.

    Tip

    The green tip is for practical advice. Here: the bound \(1/(4n\varepsilon^2)\) is worst-case, since \(p(1-p)\) is largest at \(p = 1/2\).

    Watch out

    The orange warning is for common mistakes. Consistency says nothing about how fast \(\hat{p}\) converges—for that you need the variance.

    Code

    Code blocks get a label (language or filename) and a copy button. Here's a simulation that flips a fair coin at increasing sample sizes:

    coin_flips.R
    set.seed(2026)
p <- 0.5
n <- c(10, 100, 1000, 10000)

estimates <- sapply(n, function(k) mean(rbinom(k, size = 1, prob = p)))

data.frame(
  n         = n,
  estimate  = estimates,
  abs_error = abs(estimates - p),
  std_error = sqrt(p * (1 - p) / n)
)

    Short output can go in an unlabeled block. Leave out the label row entirely:

    > mean(rbinom(1e6, 1, 0.5))
[1] 0.500213

    Tables

    Tables scroll sideways on narrow screens instead of breaking the layout. Numeric columns are right-aligned with the num class so decimals line up.

    Exercise: how many flips for a margin of error of 0.01?

    Using the worst case \(p = 1/2\) and a 95% normal approximation, we need \(1.96 \sqrt{0.25 / n} \leq 0.01\), so

    \[ n \geq \left(\frac{1.96 \times 0.5}{0.01}\right)^2 \approx 9{,}604. \]

    Roughly ten thousand flips, which matches the table.
